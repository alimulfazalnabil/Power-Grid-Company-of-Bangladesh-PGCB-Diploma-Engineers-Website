# Azure Terraform Infrastructure

This stack provisions production-grade Azure infrastructure for the PGCB CMS platform with reusable modules and environment-based variable files.

## Modules

- `network`: VNet and segmented subnets
- `monitoring`: Log Analytics + Application Insights
- `acr`: Azure Container Registry (private)
- `aks`: Kubernetes cluster with managed identity and ACR pull access
- `postgres`: PostgreSQL Flexible Server with private networking and geo-redundant backups
- `redis`: Azure Cache for Redis with private endpoint
- `storage`: Blob storage with private endpoint and retention policies
- `keyvault`: Azure Key Vault with private endpoint
- `frontdoor`: Azure Front Door Premium with WAF and path routing

## Remote State

- Backend config is defined in `backend.tf` using Azure Storage.
- Do not use local state for shared environments.
- Configure Azure RBAC so only pipeline identities can apply changes in production.

## Environment Files

- `environments/dev/dev.tfvars`
- `environments/staging/staging.tfvars`
- `environments/production/production.tfvars`

## Apply Order

1. Initialize Terraform:

   terraform init

2. Format check:

   terraform fmt -recursive

3. Validate:

   terraform validate

4. Plan for environment:

   terraform plan -var-file=environments/production/production.tfvars

5. Apply:

   terraform apply -var-file=environments/production/production.tfvars

Repeat with `staging.tfvars` and `production.tfvars`.

## Required Runtime Secret Pattern

Passwords are generated by Terraform and should be synchronized into Key Vault during deployment. Application workloads should consume secrets from Key Vault via AKS workload identity, not from source control or static manifests.

## Notes

- All state should remain in remote backend storage.
- Front Door origin hostnames should point to your AKS ingress public FQDNs or edge ingress endpoints.
- Redis, Storage, and Key Vault are private-endpoint enabled.
